# 08. AI 기능 연결

## 배경/목적

Phase 1~7에서 "AI 추천은 Phase 8에서 연결"로 미뤄뒀던 3곳(팀장 후보 추천, 팀장 투표 동률 추천,
공모전 카테고리 추천)을 실제로 연결한다.

## 엔티티 · 필드 정의

새 엔티티/컬럼 없음. 기존 `Message.metadata`(JSON 텍스트)에 추천 결과를 실어 카드 메시지로
내려준다.

## 결정사항

- **AI 연동 방식**: 이 프로젝트에는 실제 LLM 연동이 없고 `global/ai/AiClient` 인터페이스 +
  `MockAiClient`(랜덤/고정 로직) 하나뿐이다 (기존 프로젝트 AI 요약 기능과 동일한 패턴). Phase 8도
  같은 패턴을 따라 `AiClient`에 메서드 3개를 추가하고 `MockAiClient`가 셔플/랜덤으로 응답한다.
  실제 LLM으로 교체하려면 `AiClient`의 새 구현체만 추가하면 되도록 인터페이스 경계를 맞췄다.
- **팀장 후보 AI 2명 추천**: `ChatbotOrchestrationService.recordGreetingAndAdvance`가
  `LEADER_NOMINATION_CARD`를 발행할 때 `AiClient.recommendLeaderCandidates`로 최대 2명을 뽑아
  메시지 문구 + 메타데이터(`aiRecommendedTeamMemberIds`)에 포함한다. **정보성 표시일 뿐** — 실제
  후보 지정(`isPreLeaderCandidate`)이나 투표 로직에는 영향을 주지 않는다.
- **팀장 투표 동률 → AI 추천 수락**: `LeaderElectionService.tally()`의 동률 분기에서
  `AiClient.recommendTiebreakLeader`로 1명을 추천해 `LEADER_VOTE_CARD` 메타데이터에
  `aiRecommendedTeamMemberId`로 포함한다. 신규 API `POST /api/teams/{teamId}/leader-votes/ai-recommendation/accept`
  — 활성 팀원 누구나 호출 가능(선착순 1명이 확정, 이후 팀 상태가 `LEADER_DECIDED`로 바뀌므로 뒤늦은
  다른 팀원의 요청은 자연히 `INVALID_TEAM_STATUS`로 막힘). 서버가 별도 상태를 저장하지 않고
  **가장 최근에 발행된 `LEADER_VOTE_CARD` 메시지의 metadata를 읽어** 추천 후보를 판정한다.
- **공모전 카테고리 AI 추천**: `ChatbotOrchestrationService.advanceToContestSelecting`이
  `Team.preferredCategory` 기준으로 열려있는(`OPEN`) 공모전을 조회(기존
  `ContestRepository.findAllWithFilterAndDeadlineAsc` 재사용)한 뒤 `AiClient.recommendContests`로
  추려 `CONTEST_RECOMMEND_CARD`로 발행한다. 추천 결과가 없으면(카테고리에 맞는 공모전이 아예 없음)
  카드 없이 기존 안내 문구만 발행한다.
- **공모전 투표 동률은 대상 아님**: 04-contest-voting.md에서 이미 "AI 추천 수락 경로 없음, 재투표만"으로
  확정했으므로 그대로 유지. `ContestVotingService.resolveDeadlineIfDue`의 "투표 참여자 0명" 무작위
  선택도 Phase 7에서 이미 구현된 그대로 유지 — AI 추천으로 교체하는 건 이번 스코프에 포함하지 않음
  (실제 LLM이 붙기 전까지는 무작위 선택과 실질적 차이가 없어서 우선순위를 낮춤).
- **`@챗봇` 자유 질의 (역할 분담/타임라인 추천 등)**: [requirements.md](../requirements.md)
  "챗봇 요구사항 2번"에 처음부터 있었지만 어느 Phase 계획에도 실제 구현 태스크로 잡힌 적이
  없어 빠져 있었다(구현 현황 확인 중 발견, 2026-07-30). `IN_PROGRESS_PROMPT` 안내 문구에만
  존재하고 실제 동작하는 로직은 없던 상태였는데, 이번에 뒤늦게 연결했다. 채팅 메시지가
  `"@챗봇"`으로 시작하면 자유 질의로 간주해 `AiClient.answerTeamQuestion`으로 답변을 받아
  챗봇 메시지로 발행한다. `Team.chatbotEnabled`가 꺼져있으면 응답하지 않는다(기존 챗봇
  on/off 토글을 그대로 존중). 특정 `TeamStatus`로 제한하지 않고 어느 단계에서든 멘션하면
  응답한다 — 요구사항 원문이 단계 제한 없이 "말 걸기 가능"이라고만 돼 있었기 때문.

## 구현 현황 (Phase 8 완료)

- `global/ai/AiClient` — `recommendLeaderCandidates`, `recommendTiebreakLeader`, `recommendContests`
  3개 메서드 추가. `MockAiClient`는 셔플 후 앞에서 N개를 뽑는 방식(팀장 후보 2명, 공모전 3개)과
  랜덤 1명 선택(동률 추천)으로 구현.
- `ChatbotOrchestrationService`에 `ContestRepository`, `AiClient` 의존성 추가. 챗봇 도메인이
  contest 도메인의 리포지토리를 직접 참조하지만, 서비스 간 순환 의존은 아니다(contest →
  chatbot 방향 호출만 존재, chatbot → contest는 리포지토리 read만).
- `LeaderElectionService`에 `MessageRepository`, `AiClient` 의존성 추가.
  `acceptAiRecommendation(teamId, memberId)` 신규 메서드 — `MessageRepository`에
  `findFirstByTeam_TeamIdAndMessageTypeOrderByCreatedAtDesc` 추가해 최신 카드 메시지를 조회.
- 에러코드 `TeamErrorCode.NO_PENDING_AI_RECOMMENDATION`(400), 성공코드
  `TeamSuccessCode.AI_RECOMMENDATION_ACCEPTED` 추가.
- 컨트롤러: `LeaderController`에 `POST /api/teams/{teamId}/leader-votes/ai-recommendation/accept` 추가.
- 테스트: `LeaderElectionServiceTest`(AI 추천 수락 성공/실패 케이스 4개 추가),
  `ChatbotOrchestrationServiceTest`(공모전 추천 카드 발행/미발행 케이스 2개, `@챗봇` 멘션 응답/
  무시/챗봇꺼짐 케이스 3개 추가, 기존 케이스에 AI 추천 스텁 반영).
- `@챗봇` 멘션: `AiClient.answerTeamQuestion(question)` 추가, `MockAiClient`는 "역할"/"타임라인"·
  "일정" 키워드로 분기하는 고정 템플릿 응답. `ChatbotOrchestrationService.respondToMentionIfAny`
  신규 — `ChatWebSocketController.sendMessage`가 `recordGreetingAndAdvance` 호출 직후 항상
  호출한다(멘션이 아니면 즉시 리턴하므로 비용 적음).

## 미정 / 추후 확인 필요

- 실제 LLM 연동(OpenAI/Anthropic 등)은 이번 스코프 밖 — `MockAiClient`를 대체할 실제 구현체를
  붙이는 작업은 AI 요약 기능과 함께 별도로 논의 필요.
- `acceptAiRecommendation`은 동시성 가드가 없다(두 팀원이 거의 동시에 눌러도 낙관적 락 없음) —
  이 프로젝트의 다른 투표 로직들도 동일 수준이라 이번에는 맞춰서 그대로 둠.
